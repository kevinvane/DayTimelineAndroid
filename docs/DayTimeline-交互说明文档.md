## 1. 交互状态流转

```
                    ┌───────────────────────────────────────┐
                    │            浏览态                      │
                    │  滚动 · 点击日程 · 长按日程              │
                    └──┬────────────┬─────────────┬─────────┘
         点击空白区域     │            │ 长按日程      │ 点击日程
         ↓               │            ↓             ↓
    ┌─────────────┐      │      ┌────────────┐   触发点击事件
    │ 新建编辑态   │      │      │ 编辑态      │  （状态不变）
    │ 默认 1 小时  │      │      │ 移动/改时长  │
    └──────┬──────┘      │      └──┬───┬───┬──┘
           │ 完成 ↓      │    完成 ↑ │   │ ↑ 取消
           │      ┌──────┴──────────┘   └─────┴──→ 浏览态
      触发新建事件      │
           │           │
           └───────────┘
```

只有**两个状态**：浏览态与编辑态。编辑态又分「新建」（点空白进入）与
「编辑已有」（长按进入）两种来源。

### 1.1 状态迁移表

| 起始 | 操作 | 目标 | 副作用 |
|---|---|---|---|
| 浏览 | 点击空白 | 编辑态·新建 | `onEnterEditing(draft)`，草稿 `isCreating = true` |
| 浏览 | 点击日程块 | **浏览态**（不变） | 选中描边 + `onEventClick(event)` |
| 浏览 | 长按日程块 | 编辑态·编辑 | 选中描边 + `onEventLongClick(event)` |
| 浏览 | 纵向滑动 | 浏览态 | 滚动（自身模式）或让位外层（外部模式） |
| 编辑态 | 拖块体 / 拖手柄 | 编辑态（不变） | 只改草稿，**不发任何回调** |
| 编辑态 | `confirmEdit()` | 浏览态 | **唯一**发出数据变更的出口 |
| 编辑态 | `cancelEdit()` | 浏览态 | `onEditCancelled()`，**零数据** |
| 编辑态 | 点外部（未接管时） | 浏览态 | 同 `cancelEdit()`（FI-010） |
| 编辑态 | 数据回传中被编辑项消失 | 浏览态 | 自动取消（E20），同 `cancelEdit()` |
| 编辑态 | 数据回传中被编辑项时间变了 | 编辑态（保留） | 置冲突标记（E28），确认时 `hasConflict = true` |
| 编辑态 | `requestDelete()` | 浏览态 | 二次确认后 `onEventDeleted(event)` |

> **拖拽期间不发任何回调**。所有变更只在确认那一刻一次性发出。

## 2. 手势判定

组件内部有一个**手势仲裁状态机**（`GestureArbiter`），保证三种意图严格互斥：

| 意图 | 触发条件 |
|---|---|
| **滚动** | 位移超过阈值（系统标准阈值 × `dragThresholdRatio`，默认 0.3） |
| **长按** | 已触发长按超时**且全程未移动** |
| **点击** | 未触发长按**且**位移很小 |
| **拖块体** | 编辑态中按下落在编辑块上，再产生位移 |
| **拖上手柄** | 编辑态中按下落在**上**手柄，再产生位移 |
| **拖下手柄** | 编辑态中按下落在**下**手柄，再产生位移 |

两条不可回退的规则：

1. **一旦判为滚动就不可回退**为长按或点击 —— 否则「滑动列表时误触发长按」
   会造成误编辑。
2. **已进入编辑态的拖拽不会退回滚动** —— 否则长按进入编辑后无法上下微调。

### 2.1 手指操作流程

| 阶段 | 判定 | 行为 |
|---|---|---|
| 按下 | 落在上/下手柄上？ | 进入「调整时长」模式 |
| | 落在编辑块上？ | 进入「移动」模式 |
| | 落在已有日程上？ | 记为「待长按」 |
| | 落在空白处？ | 记为「待长按 / 待新建」 |
| 移动 | 位移超过阈值 | 取消「待长按」转滚动；已在拖拽则按吸附步长更新，**变化后才请求重绘** |
| | 拖到视口上下 48dp 内 | 启动边缘自动滚动 |
| 抬起 | 处于拖拽中 | **保留编辑态**，等待确认或取消 |
| | 长按已触发且未移动 | 进入编辑态（原地选中） |
| | 长按命中的是**空白** | **不进入编辑态**，等同普通点击 |
| | 未触发长按且位移很小 | 视为点击 |
| | 未触发长按且点在空白 | 进入新建编辑态 |

### 2.2 系统中断（ACTION_CANCEL）

手势被系统或父容器打断（来电、通知栏下滑、父容器抢走）时，
组件**只做清理，不按意图分派**：

- **不会**凭空触发点击
- **不会**凭空进入编辑态
- 判为滚动的仍不消费，交给父容器

用户明明是被打断，却收到一次完整操作是最难排查的一类缺陷，
因此 `ACTION_CANCEL` 与 `ACTION_UP` 走完全不同的分支。

## 3. 时间吸附规则

- **上下对称是硬要求**（D11）：距刻度线向上 7 分钟与向下 8 分钟，吸附结果应一致。
  实现采用「四舍五入到最近步长」而非「向下取整」—— 取整算子对正负方向天然对称。
- 步长 = `snapMinutes`（默认 15 分钟）。**设 `0` 关闭吸附**，
  但最短 / 最长时长兜底**仍然生效**。
- **拖拽与表单走同一套规则**（`applyEdit` 与拖拽都调 `SnapCalculator.applyRange`），
  保证上下对称。业务方在表单里填的越界值、填反的两端都会被同样地兜底。
- 合法化顺序（`SnapCalculator.applyRange`）：
  1. 先把时长上下限自身规范化 —— `minDur = max(1, minDuration)`，
     `maxDur = clamp(maxDuration, minDur, 1440)`
  2. 两端各自**吸附并钳制到 00:00–24:00**
  3. **两端填反则交换**
  4. **最长时长**：超出则从开始处截断
  5. **最短时长**：优先推结束时刻；推过 24:00 则改为拉开始时刻

## 4. 编辑态的三条硬性规则

### 4.1 取消绝不产生任何数据变更（D3）

这是本组件最硬的一条约定，**由 `:library` 与 `:r8test` 的仪器测试分别守住两侧**。

- `cancelEdit()` 走 `EditSession.cancel()`，返回一个**无字段**的结果对象 ——
  在**类型层面**就无法表达一次数据变更。
- 取消路径唯一允许的回调是 `onEditCancelled`，它不携带任何数据，
  只能用于统计「编辑完成率」。
- 确认编辑只有 `confirmEdit()` 一个出口，**不存在**「先确认再回滚」的写法。

「取消」包含四条路径：显式 `cancelEdit()`、FI-010 点外部、E20 自动取消、
业务方接管后自行关闭表单/详情。四条**都不得**发出任何数据变更通知。

### 4.2 退出编辑态即清干净（AD-25）

确认、取消、删除、E20 自动取消**共用同一个出口** `clearEditState()`，
「退出编辑态即清干净」不靠逐处记忆：

| 状态 | 漏清的后果 |
|---|---|
| `selectedId` | 选中描边残留到下次刷新 |
| `editTakenOver` | FI-010「点外部取消」被静默禁用 |
| 边缘滚动任务 | handler 上留一个空转的 Runnable |

> 曾出现过「自动取消与用户取消状态不一致」的缺陷：自动取消只清了 `editSession`，
> 漏了 `selectedId`，导致描边残留。

### 4.3 业务方接管后的退出路径（§8.2.1）

当业务方用 `EditController.onEnterEditing` 返回 `true` 接管时：

| 情形 | 行为 |
|---|---|
| 未接管（默认） | 点编辑块外部 → 视为取消，语义与 `cancelEdit()` 完全一致 |
| **已接管** | 点编辑块外部**不触发取消**，退出路径完全交给业务方 |

**理由**：接管后弹出的表单是**组件外部的窗口**。若表单非模态，用户点击时间轴
会触发 FI-010 → 组件取消编辑，而表单还开着 —— 产生「表单开着但编辑态没了」
的不一致状态。

**接管期间仍然允许拖拽**：拖拽只改草稿，最终以业务方提交时的值为准。

> ⚠️ **接管后你必须自己实现全部三个出口**（完成 / 取消 / 删除）。
> 组件不再响应 FI-010，不会替你收尾。

## 5. 边缘自动滚动（P2）

拖动块到视口上下边缘时自动滚动，**跟随被拖动的块，而非手指**。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `edgeAutoScrollEnabled` | `true` | 总开关 |
| `edgeScrollTriggerSize` | `48dp` | 进入触发区的距离 |
| `edgeScrollStepSize` | `8dp` | 每步位移 |

仅在**编辑态拖拽中**生效，浏览态滑动是用户自己的滚动，不走这里。

## 6. 滚动行为

| | 自身滚动 `self`（默认） | 外部容器滚动 `external` |
|---|---|---|
| 高度约定 | 填满父容器 | `wrap_content` = `24 × 格高 + 上下留白` |
| 纵向手势 | 组件消费 | **不消费**，让给外层 |
| 旋转后位置 | 组件自动恢复（`onSaveInstanceState`） | 由外层容器负责 |

> ⚠️ **外部滚动模式下，组件不消费纵向手势**，父容器才能正常滚动。
> 反过来，**自身滚动模式下组件会主动 `requestDisallowInterceptTouchEvent(true)`**
> 拦住父容器，避免下拉刷新抢走手势（E29）；手势结束时它会主动归还。
>
> 外部滚动模式必须由业务方把高度设为 `wrap_content`，否则会截断内容或留白过多。
> **组件不主动校验。**

## 7. 当前时间线

| 项 | 行为 |
|---|---|
| 显示条件 | 查看的日期为今天（`nowIndicatorTodayOnly`，默认 `true`） |
| 刷新 | 每 30 秒；界面离开时停止，回到时恢复 |
| 与整点标签重叠 | 默认跳过被覆盖的整点标签（`nowIndicatorSkipOverlappingHourLabel`） |
| 首次显示 | 自动定位到当前时间，上移约三分之一屏（`autoLocateOnFirstShow`） |

非今天时组件定位到 00:00（顶部）—— 没有「当前时间线」可言。
若外部调用了 `setNowMinute(...)`，当前时间被**钉死**，30 秒定时器不再覆盖它。

## 8. 无障碍交互

组件通过 `androidx.customview` 的虚拟视图为**每个日程块**与**空网格**暴露无障碍节点：

| 动作 | 触发 | 行为 |
|---|---|---|
| `ACTION_CLICK` | 读屏单击 | 等同手指单击：点已有块 → `onEventClick`；点空白 → 新建编辑态 |
| `ACTION_LONG_CLICK` | 读屏长按 | 等同手指长按 |

读屏可获知内容、起止时间与「已过 / 进行中 / 未开始」状态。
块高不足以显示两行文字时自动降级，**只读屏不显示文字**。

> 触摸热区 ≥ 48dp 是硬要求（`minTouchTarget` / `editHandleTouchSize`），
> 视觉可以更小（编辑手柄为「视觉 6dp + 热区 48×48dp」）。

## 9. 编辑态期间的数据一致性

业务方通过 `submitEvents()` 回传新数据时，组件按三种情形处理：

| 情形 | 行为 |
|---|---|
| 新建态（`origin == null`） | **不受影响**，继续编辑（E21） |
| 被编辑的日程**已不在**新数据中 | **自动取消**，等同 `cancelEdit()`（E20） |
| 被编辑的日程**仍在但时间变了** | **保留编辑态**，置冲突标记（E28） |

E20 必须计入「编辑取消」事件，否则 §15「编辑完成率」的分母会漏掉这部分、
完成率虚高。

E28 的冲突标记会让 `onEventModified` 的 `hasConflict` 为 `true` ——
组件**保留了用户的编辑状态**，是否覆盖由业务方决定。

> **组件不修改业务方数据**。你若在编辑期间改了同一条日程，
> 需要自己在 `hasConflict == true` 时决定「我的」和「用户的」谁作数。

## 10. 边界与已知限制

| 限制 | 说明 |
|---|---|
| 组件**不内置**编辑按钮 | 「完成/取消/删除」必须由业务方经 `EditController` 接管（PRD v1.22 已取消「可配置是否内置」这项需求） |
| 组件**不提供**详情界面 | 单击只发 `onEventClick`，UI 由业务方实现 |
| 组件**不内置**输入控件 | 拖拽与表单合法化由组件负责，输入控件由业务方负责 |
| 选中态描边 | 常规态**不描边**；仅选中态描边加粗至 `blockStrokeWidth` |
| 色条内缩只影响绘制 | 触摸热区仍是整块，文字左边界同步让开 |
| 仅单日 | 不支持跨天，跨天由业务方在更高层实现 |
| 最小粒度为分钟 | 不支持秒 |
